# Balance & Gameplay Pass — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the economy problems found by the playtest/simulation feedback, make light part of the rules, and prove the new pacing with a simulator that runs the game's own code.

**Architecture:** Every tunable number moves into `src/core/tuning.ts`. A headless simulator (`tools/sim/sim.ts`) drives the real `src/core` functions (tick, collect, buy, sail, build, pass) with two player profiles and reports pacing, income shares, leftovers, net levels and starlight. Mechanics change first with provisional numbers (unit tests pin behaviour, not exact values); Task 9 tunes `tuning.ts` until the spec targets hold, then locks them in `tests/sim/targets.test.ts`.

**Tech Stack:** TypeScript, Vitest (simulator runs under Vitest/Node), existing three.js UI.

**Spec:** `docs/superpowers/specs/2026-11-25-balance-design.md` (targets §2, changes §3, clarifications §5.5).

## Global Constraints

- Author decisions: double-collect hidden (1A); materials do not carry to a new sea, converted to starlight (2A).
- Keep: same reward per minute for every destination within a sea; voyage lengths 15 m / 1 h / 4 h / 8 h; copy, goal bar, "约 X 分钟", ending.
- Old saves load; no new required save fields without defaults.
- All text through `t()` (zh + en); UI values from `theme.css`.
- Randomness injectable in core (`rng` param) so sim and tests are deterministic.

## Review Focus

1. A save from before this change, loaded mid-sea with a boat on a voyage → loads, voyage settles with the new haul formula, no NaN anywhere in materials. (Task 3 test)
2. Recycler with a source below its threshold, or a target material at 0 → converts nothing, never makes a material negative. (Task 6 test)
3. Passing the light with huge materials (1e12) → starlight bonus is capped, finite. (Task 7 test)
4. Test build ×1000 time with the recycler and night bonus running → no negative or NaN values after 1 simulated week. (Task 9 sim run)
5. Night bonus at the cycle boundary (sky phase wraps) → no double counting. (Task 2 test)

### Task 1: Simulator that reproduces the feedback

**Files:** Create `tools/sim/sim.ts`, `tools/sim/report.ts`, `tests/sim/baseline.test.ts`; Modify `package.json` (script `"sim": "vitest run tests/sim --reporter=verbose"`).

**Interfaces (produces):**
- `type Profile = { name: string; checksAt(dayMs: number): number[]; tapsPerCheck: number }` — `IDEAL` (check every 10 min, boat never idle), `NORMAL` (3 checks/day at 08:00, 13:00, 21:00, 3 min each, 5 taps), `KEEN` (hourly 08–23, 10 taps).
- `simulate(profile: Profile, opts: { seas: number; maxDays: number; rng?: () => number }): SimReport`
- `SimReport = { seas: { sea: SeaId; days: number; lightAt: number[] /* day each light level reached */; buyRatio: number; share: { net: number; boat: number; islands: number; taps: number; other: number }; leftoverRatio: Partial<Materials>; maxNet: number; starlight: number }[]; talentFill: number }`
- Player policy at each check: collect chest, unload, build boat when possible, buy in order light → recycler → island buildings → net/storage → speed/cargo (cheapest first within a group, only if affordable), learn the cheapest learnable talent, pass the light when possible, sail to the longest voyage that returns before the next check (else shortest).
- Income is attributed by source by diffing materials around each source call.

- [ ] Test `baseline.test.ts` (current numbers): IDEAL sea 1 boat share > 0.7; tap value in fog sea < 2 s of income; first pass starlight ≥ 50. Run → FAIL (no sim) → implement → PASS. These reproduce the feedback; Task 9 replaces them with target tests.
- [ ] Commit `feat(sim): headless simulator on the real rules`.
